WARREN

The floor generator for the WANDERER descent. The path is a walk that turns across a 56×56 grid, so a floor is a wandering warren rather than a strip — “depth” is distance along the path, not a coordinate. Ground only: no entities, no ambushes, no light, no rendering.

$ dotnet run --project DofusSlice.Sim -- warren 5 # print a floor map $ dotnet run --project DofusSlice.Sim -- warren 5 fog # as the player would see it $ dotnet run --project DofusSlice.Sim -- warren stats # measure the grammar $ dotnet run --project DofusSlice.Sim -- warren verify # 400 floors, BFS-passable $ dotnet run --project DofusSlice.Sim -- warren era # expressive range, 600 floors

Red floor was never spikes — and colouring both red was my mistake. Red meant
    “ground only two cells across”, a chokepoint; spikes are a terrain tile. Two different things
    wearing one colour. Spikes are amber now and read as ", and the chokepoint tint has
    moved to labels → debug where it belongs, because it is an analysis of
    the floor rather than something standing on it.

What the harness caught

  

    Every number above would otherwise have been a guess. Each of these was invisible in the source
    and obvious the moment it ran.
  


  

    
01

      
A turning path severs itself

      
Making the corridor turn took 398 of 400 floors impassable. A path that
      turns can cross its own earlier ground, and a later segment's pillars, water or chasm then
      overwrite an earlier step's centre. Every centre was forced walkable at the moment it
      was walked — and later carving quietly severed the route behind it. The guarantee has to be
      applied once the floor is finished, not while it is still being written.


    
02

      
“Every row has a walkable cell” is not passability

      
Movement is orthogonal, so two cells that are merely diagonally adjacent are mutually
      unreachable. The old check passed while 24 floors in 400 were unwinnable — and
      on a one-way descent the player cannot even walk back to find out why.


    
03

      
A chasm at the wall is not a chasm

      
Halls were given a bite of void to make pushback lethal — placed at the band edge,
      where it is indistinguishable from the wall being one cell nearer and there is nothing to be
      shoved across. It fired on 22% of wide halls and produced zero holes.


    
04

      
Water was missing from the passability proof

      
The walkability test excluded void and rock but not water, so a flooded cistern counted as
      open floor and the proof would have walked a route straight across a pool.


    
05

      
The funnel ate the chokepoint

      
Width eased one step per row, so a short Throat spent every row narrowing and
      never reached its target. Tight ground measured 7.7% against a 15–35% target.


    
06

      
A flat cap cancelled the difficulty curve

      
Capping tight ground at a fixed rate silently deleted the per-floor ramp: the weights
      produced more chokepoints deeper down and the budget removed exactly the surplus, leaving
      floor 10 indistinguishable from floor 1. A cap and a curve only conflict if the cap isn't
      itself the curve.


    
07

      
And the metric broke twice, the same way

      
Chained throats read 0 because the stats found segment boundaries by kind
      change, which merges two consecutive Throats into one. Fixed once with a segment index —
      then a rewrite dropped that field and it broke again. A metric that cannot observe the thing it
      counts is indistinguishable from a broken feature.

  


  

    
What this is not. It cannot tell us whether the game is fun. The design
    panel's advice was to cut the generator from the vertical slice, and that advice stands —
    building the visible thing first is how a project feels productive while dodging the question
    that kills it. Step zero is still owed: one unit, one command window per turn, twenty minutes.
